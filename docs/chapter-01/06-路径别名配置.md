## 1. 为什么需要路径别名？

### 1.1 相对路径的痛点

```typescript
// ❌ 相对路径：难以维护、容易出错
import { UserService } from '../../../services/user/UserService'
import { formatDate } from '../../../utils/date/format'
import { API_CONFIG } from '../../../config/api'
```

**问题**:
- 路径冗长，难以阅读
- 移动文件需要更新大量导入
- 难以确定文件在项目中的位置

### 1.2 路径别名的优势

```typescript
// ✅ 路径别名：简洁、清晰
import { UserService } from '@/services/user/UserService'
import { formatDate } from '@/utils/date/format'
import { API_CONFIG } from '@/config/api'
```

**优势**:
- 路径简洁，易读易维护
- 移动文件无需更新导入
- 清晰的文件组织结构

## 2. TypeScript 配置

### 2.1 配置 tsconfig.json

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@/components/*": ["src/components/*"],
      "@/views/*": ["src/views/*"],
      "@/api/*": ["src/api/*"],
      "@/utils/*": ["src/utils/*"],
      "@/stores/*": ["src/stores/*"],
      "@/types/*": ["src/types/*"],
      "@/assets/*": ["src/assets/*"],
      "@/styles/*": ["src/styles/*"],
      "@/router/*": ["src/router/*"]
    }
  }
}
```

**配置说明**:
- `baseUrl`: 基础路径，`.` 表示项目根目录
- `paths`: 路径映射，`@/*` 映射到 `src/*`

### 2.2 路径别名设计原则

```json
{
  "paths": {
    // ✅ 推荐：简洁的别名
    "@/*": ["src/*"],

    // ✅ 推荐：常用路径单独映射
    "@/components/*": ["src/components/*"],
    "@/utils/*": ["src/utils/*"],

    // ❌ 不推荐：过度细分
    "@/components/common/*": ["src/components/common/*"],
    "@/components/business/*": ["src/components/business/*"]
  }
}
```

## 3. Vite 配置

### 3.1 配置 vite.config.ts

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  plugins: [vue()],

  resolve: {
    alias: {
      '@': resolve(__dirname, 'src'),
      '@/components': resolve(__dirname, 'src/components'),
      '@/views': resolve(__dirname, 'src/views'),
      '@/api': resolve(__dirname, 'src/api'),
      '@/utils': resolve(__dirname, 'src/utils'),
      '@/stores': resolve(__dirname, 'src/stores'),
      '@/types': resolve(__dirname, 'src/types'),
      '@/assets': resolve(__dirname, 'src/assets'),
      '@/styles': resolve(__dirname, 'src/styles'),
      '@/router': resolve(__dirname, 'src/router'),
    },
  },
})
```

### 3.2 使用自动导入插件（可选）

**安装插件**:
```bash
pnpm add -D vite-plugin-aliases
```

**配置自动生成**:
```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { createAliases } from 'vite-plugin-aliases'

export default defineConfig({
  plugins: [
    vue(),
    createAliases({
      '@': 'src',
      '@components': 'src/components',
      '@views': 'src/views',
      // ... 其他别名
    }),
  ],
})
```

## 6. 高级配置

### 6.1 多项目路径别名

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@shared/*": ["packages/shared/*"],
      "@admin/*": ["apps/admin/src/*"]
    }
  }
}
```

### 6.2 动态路径别名

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import { resolve } from 'path'

const pathResolver = (path: string) => resolve(__dirname, path)

export default defineConfig({
  resolve: {
    alias: [
      {
        find: /@(.*)/,
        replacement: pathResolver('src/$1'),
      },
    ],
  },
})
```

**使用**:
```typescript
import { foo } from '@/utils'        // → src/utils
import { bar } from '@/api/user'     // → src/api/user
```

### 6.3 模块解析优先级

```typescript
// vite.config.ts
export default defineConfig({
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src'),
    },
    // 解析顺序
    extensions: ['.ts', '.tsx', '.js', '.jsx', '.vue', '.json'],
  },
})
```

## 7. 常见问题排查

### 7.1 路径别名不生效

**检查清单**:

1. ✅ TypeScript 配置正确
```json
// tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["src/*"] }
  }
}
```

2. ✅ Vite 配置正确
```typescript
// vite.config.ts
export default defineConfig({
  resolve: {
    alias: { '@': resolve(__dirname, 'src') }
  }
})
```

3. ✅ 重启 TS 服务器
```
VS Code: Ctrl+Shift+P → "TypeScript: Restart TS Server"
```

### 7.2 构建时找不到模块

**问题**:
```bash
Error: Cannot find module '@/utils/helper'
```

**解决**:
确保 Vite 配置中使用了绝对路径：
```typescript
import { resolve } from 'path'

alias: {
  '@': resolve(__dirname, 'src'), // ✅ 使用 resolve
  // '@': './src',                 // ❌ 相对路径可能不工作
}
```

### 7.3 类型提示不工作

**解决**:
1. 重启 VS Code
2. 检查 `jsconfig.json` 或 `tsconfig.json`
3. 确保 `include` 包含了所有源文件

## 8. 最佳实践

### 8.1 路径别名命名规范

```json
{
  "paths": {
    // ✅ 简洁、语义化
    "@/*": ["src/*"],
    "@/components/*": ["src/components/*"],
    "@/views/*": ["src/views/*"],

    // ❌ 避免：过长的别名
    "@srcComponents/*": ["src/components/*"],

    // ❌ 避免：容易混淆
    "@c/*": ["src/components/*"],
    "@v/*": ["src/views/*"]
  }
}
```

### 8.2 导入顺序规范

```typescript
// 1. Node.js 内置模块
import { useState } from 'vue'

// 2. 第三方库
import { useRouter } from 'vue-router'

// 3. 路径别名（按字母顺序）
import { formatDate } from '@/utils/date'
import { validateEmail } from '@/utils/validate'

// 4. 相对路径
import './styles.css'
```

### 8.3 避免过度嵌套

```
src/
├── components/
│   └── EzButton.vue        # ✅ 扁平结构
├── api/
│   └── user.ts             # ✅ 按功能分类
├── utils/
│   ├── date.ts             # ✅ 单一职责
│   └── validate.ts
```
