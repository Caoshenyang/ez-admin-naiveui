# 核心行为准则

强制执行的开发规则，违反这些规则将导致严重问题。

## 1. Git 提交规范

**禁止私自提交**: 严禁在没有用户明确指示的情况下执行 `git commit` 或 `git push`。所有代码提交必须等待用户确认后执行。

## 2. 自动校验规范

**禁止自动校验**: 禁止主动运行 `pnpm type-check`、`pnpm lint` 或任何 `build` 命令。

- 用户将自行执行类型检查和构建
- 若代码报错，立即停止并向用户报告
- 严禁自行通过重复运行命令尝试修复

## 3. 错误处理规范

**禁止循环修复**: 若代码报错，请立即停止并向用户报告，严禁自行通过重复运行命令尝试修复。

- 报告错误时提供清晰的错误信息和上下文
- 建议可能的修复方案，但不自动执行
- 等待用户指示后再进行修复

## 4. 职责边界

**只管生成，用户校验**: 你的职责是根据逻辑需求输出高质量代码。调试、环境纠错与类型检查由用户在本地控制。

## 5. 包管理规范

**包管理约束**:
- 必须使用 `pnpm`
- 安装包时使用 `--silent` 以减少终端输出占用上下文空间
- 示例: `pnpm add <package> --silent`

## 6. 类型安全规范

**严格类型安全**:
- **严禁使用 `any` 类型**
- **严禁使用 `as xxx` 类型断言**绕开类型约束
- 必须通过正确的类型设计（继承、泛型、类型守卫等）解决类型问题
- 所有公共 API 必须有明确的类型定义

## 7. 进度同步

**同步更新进度 (Mandatory)**:
- 每一项子任务完成后，**必须立即修改并保存 `CLAUDE.md` 文件**
- 将对应任务标记为 `[x]`
- 在任务末尾标注完成时间（如：`[x] 任务名 (2026-02-12)`）

## 开发命令参考

- **启动预览**: `pnpm dev` (由用户手动执行)
- **类型检查**: `pnpm type-check` (由用户手动执行)
- **生产构建**: `pnpm build`
- **代码格式化**: `pnpm format`
